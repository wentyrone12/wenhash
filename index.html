CRYPTOGRAPHY, WITHOUT THE MYSTERY

How WenHash
works.

Each mode solves a different problem. Choose based on whether you need a fingerprint, a salted verifier, or reversible confidentiality.

#
01 / HASH

A one-way fingerprint

A hash function maps input text to a fixed-size digest. A tiny change in the input changes the output, but there is no standard “decrypt” operation.

Plain text→SHA-256→Digest
  • Same text gives the same SHA digest.
  • Can check integrity or compare known candidates.
  • Not suitable by itself for storing passwords.
⟡
02 / SALTED HASH

Same text, different record

WenHash creates a random 16-byte salt and runs PBKDF2-HMAC-SHA-256 for 600,000 iterations. The record keeps both the salt and derived hash.

Text + salt→PBKDF2→Record
  • The salt is not secret and cannot be decoded.
  • Save the full record to verify the text later.
  • Salted hash output is still one-way.
⌑
03 / ENCRYPTION

Confidential and reversible

AES-256-GCM protects the message with authenticated encryption. PBKDF2 derives a key from your password and a random salt; a random IV is used for AES-GCM.

Plain text→AES-GCM→Ciphertext
  • Needs the same password and complete JSON record to decrypt.
  • Authentication fails if the password is wrong or data is changed.
  • Keep the password separate from the record.
!
Important security limit

Nothing can promise a tool is “unhackable.” A weak password can be guessed, and malware or an unsafe device can expose your input. WenHash is an educational local-browser tool, not an independently audited security product.

EDUCATION
What cannot be done?

There is no genuine “hash to original text” or “salt to original text” converter. Anyone claiming to reverse every arbitrary hash or salt is misleading you. The safe and valid alternatives are candidate verification and decryption of actual encrypted data.
